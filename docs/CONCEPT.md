# ininet-win — Концепция (Windows-версия)

`ininet-win` — Windows-сборка сетевого инструмента **ininet**:

1. **Что у меня в сети?** — сканирование хостов, портов, сервисов.
2. **Что сейчас происходит?** — живые соединения, кто с кем разговаривает.

Это **отдельный репозиторий** и **отдельная ветка развития** от Linux-версии
([SkilinPur/ininet](https://github.com/SkilinPur/ininet)). Общая идея и UX — одинаковые, но
платформенный слой полностью разный, поэтому код платформы не пересекается.

---

## Почему отдельное репо

- **Платформенный слой не совместим**: Windows API (WinAPI, WMI, Get-NetTCPConnection,
  WinDivert) кардинально отличается от Linux (`/proc/net`, `ss`, netlink, pat).
- **Разные требования**: на Windows часто нет прав администратора, другой firewall,
  другой способ получать таблицу соединений.
- **Разные релизы**: Windows-пользователи ждут `.exe`/`.msi`, Linux — пакет/AUR.
- **Общее ядро** (алгоритмы, модели данных, формат вывода) переносится между репо
  вручную или через общий пакет — решается позже.

## Ключевые отличия от Linux-версии

| Аспект | Linux (`ininet`) | Windows (`ininet-win`) |
|---|---|---|
| Права | Часть через root | Часто без админа; часть функций требуют elevated |
| Сканирование | raw sockets, ICMP | `ping` через system / ICMP через `IcmpSendEcho` API |
| Соединения | `/proc/net/tcp`, `ss` | `Get-NetTCPConnection` (PowerShell) / WMI / `psutil` |
| Обнаружение хостов | ARP из `/proc/net/arp` | ARP через `arp -a` / `Get-NetNeighbor` |
| Перехват пакетов | pcap | **WinDivert** (в крайнем случае Npcap) |
| GUI | PySide6 (позже) | PySide6 (позже), приоритет — TUI/CLI |
| Пакетирование | PyPI / AUR | PyPI + самодостаточный `.exe` (PyInstaller) |

## Технологический стек

| Компонент | Выбор | Почему |
|---|---|---|
| Язык | Python | единый с Linux-версией |
| CLI | `typer` + `rich` | единый UX |
| TUI | `textual` | современный, живые таблицы |
| Соединения | `psutil` (основа) | кроссплатформенно, без админа |
| Соединения (детально) | `Get-NetTCPConnection` через `subprocess` | точные состояния |
| ARP/соседи | `arp -a`, `Get-NetNeighbor` | без зависимостей |
| Port scan | `asyncio` + sockets | работает без админа |
| ICMP ping | системный `ping` / `IcmpSendEcho` (ctypes) | без внешних бинарников |
| Хранение | SQLite (stdlib) | как в Linux-версии |
| Пакетирование | `pyproject.toml` + PyInstaller | pip для девов, exe для юзеров |
| (позже) захват пакетов | WinDivert | если потребуется |

## Windows-специфика, которую надо учесть

1. **Права администратора**: часть функций (например, точное определение процессов для
   чужих сокетов, WinDivert) требует elevation. Нужен аккуратный механизм: проверка прав,
   понятное сообщение, опциональный перезапуск с UAC.
2. **Firewall / Defender**: сканирование сети может триггерить уведомления. Нужно
   документировать это.
3. **Кодировки**: вывод консоли Windows (cp866/cp1251/UTF-8) — использовать `rich` и
   явно настраивать UTF-8, чтобы кириллица не ломалась.
4. **PowerShell fallback**: если `Get-NetTCPConnection` недоступен (старые системы) —
   откат на `psutil`.
5. **Терминал**: Windows Terminal / conhost. Проверять работу TUI (`textual`) в обоих.
6. **Пути и временные файлы**: использовать `%LOCALAPPDATA%\ininet` для БД и кэша.

## Платформенный слой (изоляция)

Вся Windows-специфика — в `src/ininet_win/platform/`:

- `connections.py` — таблица TCP/UDP соединений (psutil → Get-NetTCPConnection)
- `neighbors.py` — ARP/соседи (`arp -a`, `Get-NetNeighbor`)
- `icmp.py` — отправка ping (system ping → IcmpSendEcho через ctypes)
- `elevate.py` — проверка прав администратора, запрос UAC

Ядро (`core/`) не знает о платформе — работает через абстракции этих модулей.

## Связь с Linux-версией

- Концепция, UX, формат вывода, модели данных — общие.
- Код платформенного слоя — разный (см. таблицу отличий).
- Возможный будущий шаг — вынести «общее ядро» в отдельный пакет, который импортируют
  оба проекта. **Сейчас НЕ делаем** — избегаем преждевременной абстракции.
